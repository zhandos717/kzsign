# KZSign — браузерная замена NCALayer (дизайн)

Дата: 2026-10-08
Статус: черновик, ждёт ревью

## 1. Цель

Chrome-расширение (MV3) для личного и командного использования, которое подписывает документы ЭЦП НУЦ РК без установленного NCALayer. Сайты продолжают работать со «старым» NCALayer API через `ws://127.0.0.1:13579` и не знают о подмене.

Идеи взяты из Doodocs Sign 1.5.1 и Договор24 Sign 1.057. Их код не копируется: оба продукта проприетарные.

### Критерии готовности v1

- Подпись `.p12` (ГОСТ 34.10-2015 и RSA) проходит на egov.kz, goszakup.gov.kz и двух внутренних сайтах команды.
- Подпись проверяется на ezsigner.kz и в настоящем NCALayer.
- Если запущен настоящий NCALayer и политика это разрешает, запрос уходит ему.
- Можно подписать локальный файл из popup и сохранить `.cms`.
- Ни один сайт не может получить подпись без подтверждения в окне расширения.

### Не входит в v1

- eGov QR (фаза 2, требует своего relay-сервера — см. §9).
- Публикация в Chrome Web Store, аналитика, локализации кроме ru.
- XML-подпись (XMLDSig) — фаза 2, если понадобится сайтам команды.
- ГОСТ 34.310-2004 (`1.2.398.3.10.1.1.1.1`): НУЦ больше не выпускает такие ключи. Импорт отклоняется с понятной ошибкой.

Тестовые ключи: `test/fixtures/nca/` (см. `NOTICE.md`).

## 2. Архитектура

```
Страница (MAIN)       Content (ISOLATED)      Service Worker                    Окна расширения
ws-shim  ──postMsg──▶ bridge ──port──────────▶ router                           confirm.html
FakeWebSocket ◀────── (MessagePort)  ◀──────── ├ ncalayer-proto                 popup.html
                                               ├ policy ──▶ native-proxy ──▶ ws://127.0.0.1:13579
                                               ├ signer ─┬ rsa  (WebCrypto)
                                               │         └ gost (JS, фолбэк WASM)
                                               ├ keystore
                                               └ confirm-manager ──▶ confirm.html
```

Сборка: TypeScript + esbuild, по одному бандлу на точку входа (`shim`, `bridge`, `sw`, `confirm`, `popup`). Без фреймворков в UI.

## 3. Компоненты

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `shim/ws-shim.ts` | Подменяет `window.WebSocket` только для `127.0.0.1\|localhost:13579`, остальные URL отдаёт оригиналу. Логики подписи нет. | — |
| `content/bridge.ts` | Создаёт `MessageChannel` со shim (не `window.postMessage("*")`), пересылает кадры в SW через `chrome.runtime.connect`. | — |
| `sw/router.ts` | Принимает кадры, берёт origin из `port.sender.origin` (не из данных страницы), отдаёт в `ncalayer-proto`. | proto, policy |
| `sw/ncalayer-proto.ts` | Разбор и формирование сообщений `kz.gov.pki.knca.commonUtils` и `basics`: `getActiveTokens`, `getKeyInfo`, `signXml` → v1 отвечает ошибкой «не поддерживается», `createCAdESFromBase64`, `createCAdESFromBase64Hash`, `signCMS`/`basics.sign`. Чистые функции. | — |
| `sw/policy.ts` | Режим `auto \| extension \| native`. В `auto`: есть ключи в keystore → extension, иначе native, если он отвечает. | native-proxy, keystore |
| `sw/native-proxy.ts` | Прозрачный проброс кадров в настоящий NCALayer. Проверка доступности с таймаутом 1.5 с, результат кэшируется на 60 с. | — |
| `sw/signer.ts` | Сборка CAdES-BES (attached/detached) на `pkijs`: signedAttrs (contentType, messageDigest, signingTime, signingCertificateV2). Опционально TSP-метка (§6). | rsa, gost, tsp |
| `sw/crypto/rsa.ts` | RSA PKCS#1 v1.5 + SHA-256 через WebCrypto (`importKey` с `extractable: false`). | WebCrypto |
| `sw/crypto/gost.ts` | ГОСТ 34.11-2015 (Стрибог 256/512) и 34.10-2015 (кривые НУЦ). Интерфейс `sign(hash, key)`, `digest(data)`. Реализация выбирается на этапе спайка (§10). | JS-либа или WASM |
| `sw/p12.ts` | Разбор PKCS#12 НУЦ (ГОСТ и RSA), извлечение ключа и цепочки сертификатов. | pkijs/asn1js |
| `sw/keystore.ts` | Хранение и разблокировка ключей (§5). | WebCrypto, storage |
| `sw/confirm-manager.ts` | Открывает `confirm.html` через `chrome.windows.create`, ждёт решение, таймаут 120 с. Одно окно на запрос, очередь. | — |
| `ui/confirm` | Показывает origin (крупно, punycode раскрыт), тип операции, владельца и ИИН/БИН сертификата, размер и SHA-256 данных, превью для текста/XML. PIN-поле. | — |
| `ui/popup` | Список ключей, импорт `.p12`, удаление, режим policy, подпись файла. | — |

## 4. Поток подписи

1. Сайт открывает `new WebSocket("wss://127.0.0.1:13579")` → shim создаёт `FakeWebSocket`, сразу `open`.
2. Кадр → bridge → `router`. Origin = `sender.origin` вкладки/фрейма.
3. `policy` решает: native → `native-proxy` пробрасывает как есть. Extension → дальше.
4. `ncalayer-proto` парсит запрос. Немутирующие запросы (`getActiveTokens`, версия) отвечаются без окна.
5. Любой запрос, использующий ключ (включая `getKeyInfo`), → `confirm-manager` → окно подтверждения.
6. Пользователь выбирает ключ, вводит PIN → `keystore.unlock` → `signer` → ответ в формате NCALayer → обратно по цепочке.
7. Отказ/таймаут/закрытие окна → ответ NCALayer `{"code":"500","message":"action.canceled"}`.

## 5. Хранение ключей

- При импорте `.p12` проверяется, что пароль подходит. Сохраняется сам `.p12` (он уже зашифрован паролем НУЦ) плюс метаданные сертификата в открытом виде: CN, ИИН/БИН, срок, алгоритм, отпечаток.
- Дополнительный слой: `.p12` оборачивается AES-256-GCM ключом, выведенным из PIN через PBKDF2-SHA256, 600 000 итераций, соль 16 байт на ключ. Хранение — `chrome.storage.local`.
- Разблокированный ключ живёт только в памяти SW. RSA импортируется как неэкспортируемый `CryptoKey`. ГОСТ-ключ — `Uint8Array`, затирается нулями после подписи. Кэш «не спрашивать PIN» — до 5 минут, по умолчанию выключен, сбрасывается при засыпании SW.
- Ограничение попыток PIN: после 5 неудач — задержка 2^n секунд (максимум 15 мин), счётчик хранится в `chrome.storage.local` по отпечатку ключа.
- Нет экспорта ключа обратно из расширения.

## 6. Метка времени (TSP)

Для CAdES-T запрос к `http://tsp.pki.gov.kz/` (host permission только на него). Включается по флагу запроса сайта или настройке. Ошибка TSP → подпись не возвращается, показывается ошибка (не тихо понижать до BES).

## 7. Модель угроз

| Угроза | Защита |
|---|---|
| Вредоносный сайт тихо получает подпись | Любая операция с ключом — только через окно расширения с PIN. Окно открывается SW, страница не может его нарисовать, закрыть или нажать. |
| Сайт подделывает origin в сообщении | Origin берётся из `port.sender`, данные страницы игнорируются. |
| Фишинговый домен похож на настоящий | В окне показываем домен в punycode-раскрытии и выделяем eTLD+1. Предупреждение, если сайт впервые запрашивает подпись. |
| Сайт подменяет подписываемые данные «под капотом» | Окно показывает SHA-256 и превью ровно тех байт, которые подписываются. |
| Перехват канала shim↔bridge другими скриптами страницы | Приватный `MessageChannel`, порт передаётся один раз при старте. Скрипты страницы всё равно могут вызывать shim — это ок, защита на шаге окна. |
| Другие расширения шлют команды | Нет `externally_connectable`. |
| Кража `chrome.storage` с диска | `.p12` зашифрован паролем НУЦ и дополнительно AES-GCM от PIN. |
| Подбор PIN | Экспоненциальная задержка (§5) + PBKDF2. |
| Компрометация зависимостей | Зависимости зафиксированы lockfile'ом, минимум пакетов, сборка без CDN, CSP `script-src 'self' 'wasm-unsafe-eval'`. |

Остаточный риск: если сайт работает на всех доменах (выбор пользователя), то пользователь может подтвердить подпись на фишинговом сайте. Окно делает это заметным, но не невозможным.

## 8. Ошибки

- Все ответы — в формате NCALayer (`code`, `message`, `responseObject`), чтобы сайты показывали свои штатные ошибки.
- SW уснул посреди операции → порт рвётся, shim шлёт `close` с кодом 1006, сайт переподключается как к обычному NCALayer.
- Неподдерживаемый метод → `code 500`, `message: "method.not.supported"`, лог в консоль SW.

## 9. Фаза 2: eGov QR

eGov Mobile не может связаться с браузером напрямую — нужен публичный relay-сервер (у Doodocs это `qr.wasign.doodocs.kz`). Отдельный подпроект: свой сервер сессий (создать сессию → QR → eGov Mobile забирает данные и кладёт подпись → расширение опрашивает). Свой spec после v1.

## 10. Тестирование

- **Спайк перед реализацией `gost.ts`:** подписать тестовым `.p12` НУЦ (ГОСТ 2015) кандидатом-JS-библиотекой и `gogost` в WASM, проверить подпись через OpenSSL/ezsigner, сравнить с тестовыми векторами ГОСТ Р 34.11-2012 / 34.10-2012. Берём JS, если он проходит векторы и подпись валидна; иначе WASM.
- Юнит (vitest): `ncalayer-proto` на записанных кадрах реального NCALayer, `p12`, `signer` (подпись → разбор → проверка), `keystore` (шифрование, лимит PIN), `policy`.
- Интеграционные (Playwright с загруженным расширением): тестовая страница, открывающая WebSocket на 13579 → окно подтверждения → валидная подпись; отказ; таймаут.
- Ручной чек-лист: egov.kz, goszakup.gov.kz, внутренние сайты.

## Дополнения после ревью плана 2

- Окно подтверждения: кнопка подписи активна только через 1 с после получения окном фокуса, без autofocus (защита от перехвата ввода, когда окно всплывает во время печати).
- Очередь подтверждений: не больше 1 запроса на сокет и 5 всего; закрытие сокета снимает его запросы.
- Лимит попыток пароля защищает только от перебора через UI. От офлайн-перебора скопированного `chrome.storage` защищает лишь PBKDF2 (600 000 итераций).
- В режиме проброса настоящий NCALayer видит origin `chrome-extension://…`, а не сайта.

## Окно подтверждения на странице (после ручного теста)

Отдельное окно Chrome на macOS уходит на другой рабочий стол, если Chrome развёрнут на весь экран. Поэтому для запросов из верхнего фрейма окно показывается на самой странице:

- iframe `chrome-extension://<id>/confirm.html#<token>` (другой origin — страница не читает содержимое и не вводит текст), вставлен мостом в **закрытый** shadow root, стили inline с `!important`;
- кнопка «Подписать» активна только пока IntersectionObserver v2 (`trackVisibility`) подтверждает, что окно полностью видно, не перекрыто, не прозрачно и не искажено, и через 1 с после фокуса/появления;
- если браузер не поддерживает `isVisible`, iframe не загрузился за 2 с или запрос пришёл из вложенного фрейма — отдельное окно, как раньше;
- `confirm.html` становится web-accessible: сайт может узнать, что KZSign установлен (fingerprinting). Без токена страница с ним ничего сделать не может.

### Принятый риск: фишинг пароля

Пароль ключа вводится в окне на странице, и пользователь к этому привыкает. Злой сайт может нарисовать копию окна KZSign со своим полем и получить пароль. Ключ из расширения он не получит, но пароль может подойти к файлу `.p12` на диске. Решение владельца продукта (2026-10-08): риск принят ради удобства. Кандидат на снижение риска — подтверждение подписи через Touch ID (WebAuthn PRF) вместо пароля.
