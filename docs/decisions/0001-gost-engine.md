# 0001. ГОСТ-движок

Дата: 2026-10-08. Статус: принято (спайк, `spike/gost-oracle.ts`).

## Решение

JS: `@li0ard/gostcurves@0.1.6` + `@li0ard/streebog@0.2.6` (MIT, поверх `@noble/curves` / `@noble/hashes`). WASM-фолбэк не нужен.

Риск: `gostcurves` помечена автором как alpha. Мы компенсируем это проверками на реальных данных НУЦ (ниже) и фиксируем точные версии в lockfile.

## Что оказалось у НУЦ

Тестовый ключ ГОСТ 2015 — **512-битный**, а не 256, как предполагала спецификация: закрытый ключ 64 байта, открытый 128.

| Параметр | Значение |
|---|---|
| Кривая `1.2.398.3.10.1.1.2.2.1` | совпадает с TC26 `id-tc26-gost-3410-12-512-paramSetA` (`ID_GOSTR3410_2012_512_PARAM_SET_A`) |
| Хэш | Стрибог-512; в подпись идёт в обратном порядке байтов (`reverse(streebog512(x))`) |
| Закрытый ключ в PKCS#8 | `privateKey` = OCTET STRING { OCTET STRING(64) }, little-endian → для библиотеки `reverse` |
| Открытый ключ в сертификате | OCTET STRING(128) = `X_le ‖ Y_le` → для библиотеки `0x04 ‖ reverse(X) ‖ reverse(Y)` |
| Подпись (BIT STRING, 128 байт) | две половины по 64 байта, каждая little-endian → для библиотеки развернуть каждую половину |

## Доказательства

1. Подпись тестового УЦ (`nca_gost2022_test.cer`) на сертификате `individual_valid` проверяется. Из 448 комбинаций (кривая × хэш × формат ключа × формат подписи) сошлась ровно одна:
   `MATCHES [{"curveName":"ID_GOSTR3410_2012_512_PARAM_SET_A","hn":"h512Rev","pn":"pubRevHalves","sn":"sigRevHalves"}]`
2. Открытый ключ, вычисленный из закрытого, совпадает с ключом в сертификате на той же кривой (`PUB MATCH ... privRev, revHalves`).
3. Подпись нашим ключом проверяется (`self-verify: true`), подписи недетерминированы (`k` из `crypto.getRandomValues` через `@noble/curves`).
4. Стрибог-256 на векторе M1 (RFC 6986 §10.1.2) = `9d151eef…e57b5500` ✓.
